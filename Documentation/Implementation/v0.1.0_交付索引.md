## 仓库文件

- `engine/`、`backend/`、`frontend/` 是独立构建和验证入口。Compose 与 `deploy/` 管理容器部署。
- `Documentation/Requirement/` 保存原始课程资料，`Documentation/Requirements/` 保存项目需求基线，`Documentation/Planning/` 保存详细规划，ADR 和实施记录分别位于 `Documentation/ADR/`、`Documentation/Implementation/`。
- `models/` 下的图源、渲染图和合成交接夹具用于课程交付及各工作包验收。根目录 `output/`、覆盖率、构建产物与本地运行目录由忽略规则管理。

## 基础登录与 Count 验证

- Windows amd64 上分别运行两个 Go module 的格式、静态分析、竞态测试及构建。R-001 复核 TE-C01—06、重复执行及证据顺序。后端验证真实 SQLite 上的会话生命周期、审计回滚、跨源和 CSRF 拒绝。使用 Go 1.27.4 执行 `govulncheck` 未发现可达漏洞。
- Node.js 26.13.0 上锁定安装、类型检查、6 项 Web 测试和生产构建通过。Playwright 检查 1440×900 与 375×812 视口，使用合成管理员验证键盘提交、错误凭据反馈、登录及刷新后保留深链接。
- CI 的 Compose 烟测通过 Nginx 代理检查登录、会话查询、注销及匿名拒绝。#14 的业务链路验收需要真实采集、分析与告警实现。

本轮由 Codex 辅助整理工作区、开发基础登录、补充 Count 断言及执行测试。人工评审、CI 和合并结果记录在对应 PR。
