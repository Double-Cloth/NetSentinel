2026-11-26 提交候选基线供 #8 和 #9 评审。范围覆盖 UC-04 自动采集、UC-13 自动分析与 UC-17 告警解释。独立 Count 引擎与 SQLite 基础仓储已有实现。采集、业务 API 和自动告警按下列契约在后续工作包接入。

## 概要设计

浏览器经同源 Web 代理调用 Go API。后端负责会话授权、来源配置、调度、解析、不可变原文、SQLite 发布和读模型。采集工作者从部署方授权的 SFTP 导出读取，分析工作者依次将固定输入传给独立引擎。引擎只依赖标准库，通过迭代器读取事件并向接收器写 Finding。原文和数据库位于同一持久化卷，迁移容器先于 API 启动。 [部署图](../../models/deployment-v01.svg) · [HTTP 契约](v0.1_分析规约与契约评审.md#前后端交接) · [ADR-009](../ADR/009_v0.1_采集与分析契约.md)

## 构件一，独立规则引擎

| 契约 | 字段和行为 |
| --- | --- |
| Event v1 | 必填 `schema_version=1`、`event_id`、`dataset_id`、`event_index`、`event_time_us`、`source`、`source_host`、`kind`、`src_ip`、`raw_ref`。SSH 需 `user.name`，按解析结果提供 `ssh` 详情。Nginx 需 `http.method/path/status`，`http.bytes_sent` 可缺失。原始引用由 `file_id/line_no/raw_hash` 定位。 |
| 输入顺序 | 后端将原文时间规范为 UTC 整数微秒，批内按时间和原行号稳定排序，索引从 1 递增。引擎拒绝时间倒退、索引不递增、重复 ID 或同一次运行出现不同 `dataset_id`。用于 HTTP 的 UTC 时间格式在适配边界转换。 |
| Count 规则 | `schema_version`、`rule_id`、`name`、`source`、`type=count`、`severity`、`group_by`、`where`、`window_seconds`、`threshold` 必填，`description` 可选。严格校验未知字段、谓词类型和上限。发布快照需正整数版本、规范 JSON 的 SHA-256 及语义版本。v0.1 自动链路固定使用 R-001 v1。 [规则样例](../../engine/testdata/rules/R-001.json) |
| 检测语义 | 窗口为 `[t-W,t]`，事件只在时间严格小于左边界时驱逐。同时间按索引处理。Count 在从低于阈值进入阈值时告警，跌回阈值以下后重新进入才再次告警。v0.2 Distinct 沿用阈值周期。Sequence 优先处理 finish，先判断窗口内此前的 start 是否达阈值，命中时输出全部可用 start 和当前 finish。每次 finish 均清空该组此前的 start，含未达阈值的情况。同时满足两阶段的事件仅按 finish 处理。v0.1 编译器以 `RULE_TYPE_UNSUPPORTED` 拒绝未支持类型。 |
| Finding v1 | 保留批次、规则版本、规范摘要、引擎语义版本、严重级、检测类型、类型化分组、窗口、首末证据时间、触发事件 ID/索引/时间、计数、阈值、原因码及完整有序证据。每条证据包含事件身份、UTC 微秒及原始引用。R-001 原因码为 `COUNT_THRESHOLD_ENTERED`。 |
| 版本与身份 | Fingerprint 对 `finding-v1`、批次 ID、规则 ID/版本/摘要、语义版本、类型化分组值、触发事件 ID 的规范 JSON 数组取 SHA-256。Result digest 对清空自身摘要字段后的完整 Finding 取 SHA-256。当前引擎语义为 `1.0.0`，独立于规则版本、对象 `row_version` 及 API 路径版本。 |
| 错误边界 | 编译错误提供 `code/path/message`。运行错误带 `code/phase` 和内部 cause。适配层将 initializing/reading 映射为 input、detecting/writing 映射为 detect，正式结果提交流程使用 commit。非法输入、超限、取消或接收器失败均使运行失败，清理暂存结果。 |

## 构件二，解析与任务提交

1. 领取事务记录来源配置版本、调度时刻、预期断点及领取令牌。单源活动执行用唯一约束保护。领取后关闭写事务，再访问 SFTP。测试、定时及重试均使用受授权的配置快照。
2. 从原断点读取有界字节，按 LF 切出完整行，保留原行号、字节偏移和原始行 SHA-256，区分有效、忽略和解析错误。半行留待下一次读取。稳定的原始身份为 `(source_id, generation_id, byte_offset)`，采集事件 ID 为该三元组加前置标识 `collected-event-v1` 的规范 JSON 数组的 SHA-256。手工补录沿用原有基于数据集摘要、行号、行摘要的身份。后台通过固定解析参数生成事件，错误与忽略行不进入引擎。没有有效事件时只提交尝试及可复核的原文和诊断，存在完整行才推进断点。
3. 原文写入同卷临时文件，持久化后改名为不可变对象。SQLite 保证 `UNIQUE(source_id, generation_id, start_offset)`，事件以 ID 为主键并约束 `UNIQUE(dataset_id, event_index)`。发布事务校验领取令牌、领取时配置版本及原断点，写批次、事件、诊断、断点、审计和分析意图。旧令牌或旧断点更新零行时整体回滚。配置变更或停用后，已领取的执行可以收尾并提交旧版数据，后续执行使用最新已批准配置。取消、过期或被回收的领取无法提交。
4. SSH ready 批次以批次 ID 与固定规则集摘要唯一入队，同时冻结批次及规则摘要、发布版本和引擎语义版本。Nginx 和无有效事件的输入不自动排 R-001。分析执行采用 queued → running → committing → succeeded，失败转 failed。重启保留 queued，将失去工作者的 running 或 committing 标记 failed，后续重试创建新执行并复用快照。
5. 引擎运行和结果暂存在 SQLite 写事务外完成。短发布事务按 fingerprint 插入新告警，按 `(alert_id, ordinal)` 固化证据，按 `(task_id, alert_id)` 写任务关联，同时提交审计与 succeeded。已有同指纹告警先比对 result digest，相等时仅新增任务关联，保留处置、负责人和证据；不符则整次发布失败并保留历史。发布报错或事务未提交时，暂存结果对业务查询不可见。v0.3 再接入可靠通知 Outbox。

## 风险原型与结论

| 实验 | 合成输入及预期 | 本地结果与设计调整 |
| --- | --- | --- |
| 闭合窗口与同时间顺序 | `TestCountGolden`。同组第 5 条位于 300 秒、300 秒加 1 微秒、5 条同微秒 | 通过。分别产生 1、0、1 条，最后一组以第 5 条触发且证据按 1—5 排列。保留稳定排序和严格左界驱逐。 |
| 高基数状态回收 | `TestHighCardinalityWindowReclaimsCapacity`。1024 个组填满组数与引用上限，第 1025 个组分别位于 300 秒和 300 秒加 1 微秒 | 通过。恰在边界返回 `ENGINE_RESOURCE_LIMIT`；越过 1 微秒回收后接收全部 1025 条，无告警。保留配额失败及回收边界，实际规模的内存/耗时由 #26 测量。 |
| SQLite 写竞争与可见性 | `TestWALWriterRollbackAndCommitVisibility`。两连接，第二连接禁用等待 | 通过。未提交写入不可见，竞争写返回 `SQLITE_BUSY`，回滚后第二连接可提交。采用 WAL 和短写事务，网络读取与分析不持有写锁。 |
| 多表提交与失败恢复 | `TestBatchPublicationTransactionPrototype`。临时库注入排队意图的外键失败，随后成功重试并尝试使用旧断点 | 通过。第二连接看到的断点/批次/意图由 0/0/0 一次变为 64/1/1，失败回滚时仍是 0/0/0，旧断点更新零行。业务表、原文崩溃恢复和正式告警发布分别留在 #11/#13 验收。 |
| 跨批次窗口 | `TestR001SplitBatchBoundary`。同组 4+1 条失败，首末相隔 300 秒 | 通过。两次独立 Run 共 0 条，完整快照 1 条且有 5 条证据。v0.1 采用批次内 Count，#18 使用完整快照作跨批次金标准。 |
| 远端文件身份与轮转 | OpenSSH 只读部署约束、代次和锚点检查 | 方案已提出。#11 验证授权合成源、代次文件、身份拒绝、断点和不支持轮转的明确失败；#14 测采集与告警延迟；#18 复核跨批次身份。 |
