# ADR-009 授权采集与分析契约

状态为候选设计基线，关联 #8、#9、#11、#13、#18 和变更 #58。四方确认后进入采集实现。原型结果与评审条目见 [WP-03/04 设计验证记录](../Implementation/WP-03-04_设计验证记录.md)。

## 来源授权与传输

v0.1 候选方案采用只读 SFTP，满足后端有界定位读取，并可复用部署方已有的 OpenSSH。受控 HTTPS 导出端点也可提供稳定代次，但需要部署方提供额外服务，暂留为备选。OpenSSH 支持将账号限制到只读 SFTP 子系统并禁止转发。参考 [sshd_config](https://man.openbsd.org/sshd_config) 和 [sftp-server](https://man.openbsd.org/sftp-server)。

采集实现的评审候选锁定为 `github.com/pkg/sftp v1.13.12`（BSD-2-Clause，用于 SFTP 子系统及定位读取）和 `golang.org/x/crypto v0.59.0`（BSD-3-Clause，用于 SSH 握手及固定主机密钥校验）。#11 接入前须核对实际解析出的依赖图、许可证与漏洞扫描结果，复现 Go 锁定安装，并用受控合成源验证超时、只读隔离及主机身份拒绝。本设计 PR 不改 module 依赖。[SFTP 版本与许可证](https://github.com/pkg/sftp/tree/v1.13.12) · [SSH 版本与许可证](https://pkg.go.dev/golang.org/x/crypto@v0.59.0/ssh)

- 部署者预配置授权源条目，绑定目标、端口、账号、允许的单个日志路径、主机公钥和只读凭据引用。Web 管理员只能选用条目及设置周期、解析参数和启用状态。
- 连接测试和实际拉取使用同一授权检查。每次连接核验固定主机公钥，仅连接部署授权的地址范围。部署端以隔离的低权限账号限制可读目录并阻止转发，禁止跳板、远程命令和符号链接切换出授权目录。
- 凭据以只读文件挂载到 API 容器，数据库仅记录引用。拒绝未知或更换的主机密钥，由部署者通过独立渠道核验并更新授权。API 与审计不返回私钥、远端路径配置、连接错误原文或内部路径。
- 预览最多 100 行且受读取上限及超时约束，产生独立审计，不改断点、来源健康或上次成功时间。评审起始值为默认周期 60 秒、可配 30—3600 秒、连接与握手合计 5 秒、单次远端读取尝试总计 20 秒、单行 64 KiB（含分隔符）、单次读取最多 4 MiB、全局最多 2 个采集工作者。触及读取预算且仍有完整行时，提交完整行后展示积压；当前行超过单行上限则失败。正常告警延迟候选为一个周期加 30 秒。#14 用实测确认延迟、持久卷容量和保留预算。

## 断点、原文与批次

- 来源配置以 `source_id` 及 `row_version` 管理。已启用来源每次最多一个活动执行；调度及手动重试通过同一领取路径。执行固定来源配置版本、文件代次、下一字节偏移及下一行号。提交时按已领取版本和原断点做条件更新，过期 Worker 整体回滚。
- 首版要求部署者提供只读、稳定追加的导出文件与一个预配置的只读代次文件。代次文件只包含一个不可复用的 ASCII 标识（1—64 个字母、数字、下划线或连字符，允许一个尾随 LF）。采集启用期间，导出方保证同一代次文件的已写前缀不可改。当导出需要换代时，先停用源并等待活动读取结束，再由部署者协调替换。拉取前后都检查代次，并重新读取、校验已消费前缀末端最多 4 KiB 的 SHA-256。大小、修改时间和末端摘要本身均无法证明整个前缀未被更换，因此部署方的追加保证是前置条件。来源无法提供代次、代次变化、锚点不匹配或文件短于断点时，明确失败并保留断点。v0.1 恢复由部署者恢复原代次及原文件，或在旧源停用后以新授权条目建新源并登记交接；自动 rename、copytruncate 和同名替换恢复留给 #11/#18 验证。
- 本次只消费截至最后一个 LF 的完整字节，CRLF 的两个字节均计入偏移。超过行上限且尚未发现行尾时返回显式错误；正常半行下轮从原偏移读取。空读记尝试且不建批次。全错误或忽略时保存原文和诊断，随诊断事务消费完整行，不排分析。
- 原始位置键为 `(source_id, generation_id, byte_offset)`，行号和原文 SHA-256 用于复核。批次保存半开字节区间 `[start, end)`，约束同一来源代次与起始断点的发布唯一。先把原始片段写入同卷临时文件并持久化为不可变对象，再在一个 SQLite 事务提交原文引用、ready 批次、事件、诊断、断点、审计及分析意图。回滚后回收无引用对象；清理不得触碰发布或运行中的引用。
- 固定时间参数及解析器版本。事件按 UTC 微秒、来源文件原行号排序，分配从 1 起严格递增的 `event_index`。异常和忽略行保留原行号。现有引擎原始引用继续使用 `file_id/line_no/raw_hash`，后端通过文件记录映射到代次、区间和原文。

## 自动分析与历史兼容

v0.1 运行固定发布版 R-001，对每个 ready SSH 批次单独计算 Count。Nginx 解析和浏览仍可独立验收。任务意图固定输入版本、规则版本、规范摘要、引擎语义版本，自动入队唯一键由批次及固定规则集摘要构成。执行记录与同一快照下的重试分开。Worker 用 `Run` 读取不可变输入，暂存 Finding，在同一事务内写入正式告警、证据、任务关联和 succeeded。执行失败、超限或提交失败保留失败阶段，正式结果不出现。

v0.1 沿用 `finding-v1` 和引擎语义 `1.0.0`。指纹包含 `dataset_id`、规则 ID/版本/规范摘要、语义版本、分组值及触发事件 ID。同一快照重跑将指纹用于查找已有告警，只新增任务关联，保存既有人工作业字段及证据。结果摘要用于校验回放，无权改写历史证据。

v0.2 在 #18 评审跨批次逻辑身份。提议以后端持久化来源范围、规则版本、规范摘要、语义版本、分组和稳定触发身份构成独立版本的业务去重键，保留 v1 指纹及原快照回放。重叠事件上下文用于组成不可变输入。仅截取一个时间窗口不足以证明 Count 阈值周期状态或 Sequence 的待消费状态等价，须先比较从固定历史前缀重放与显式初始状态两种方案，再确定水位和迟到处理。若修改引擎语义则另行升版，旧告警、人工处置和旧结果摘要不得重算覆盖。

工作包 #18 使用完整、固定历史前缀作为正确性基准，按事件时间和稳定原始位置总序重放，并以触发位置所属的新批次确定发布所有权。带显式初始状态的增量算法须逐条与该基准对照后才可替换；基准回放不得覆盖 v0.1 的旧 Finding 或把它迁移为新指纹。运行时超限、迟到和回填进入独立验证，水位策略确定前不得标记为跨批次支持。

## 验收边界

- v0.1 使用授权的合成源验证 TCOL-01—06/09—11，源在一次可消费范围内追加五条同组 SSH 失败后无需手动分析即可查询证据。验证断线、重试和半行均遵循已提交偏移。未支持模式在来源状态显示错误。
- v0.2 用 TCOL-07/08 复核跨批次窗口和重复调度。四条失败位于 A 批次、第五条位于 B 批次且恰在窗口右端时，v0.1 分批处理产生零告警。后续正确快照应只产生一条，五条证据可追溯，重放不重复发布。
- 需要团队确认部署方能否提供稳定代次及只读隔离方式、可接受的 v0.1 增量边界和预算。人工意见与结论由实际评审者记录。
