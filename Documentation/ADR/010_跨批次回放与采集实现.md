# ADR-010 跨批次回放与 v0.1 采集实现

状态：实现待团队评审。关联 #11、#13、#18。本记录描述当前代码的实际选择；性能预算、受控 SFTP 环境验收及人工批准仍需在 PR 记录。

## 决策与理由

- 后端使用部署者预配置的授权源目录。管理员只能按 `source_ref` 启用条目及修改周期、年份和时区；地址、远端路径、固定主机公钥及私钥文件引用不进入业务 API。目录条目创建时保存摘要，已消费数据的条目不得静默改指向其他目标。
- 新增直接依赖 `github.com/pkg/sftp v1.13.12`（BSD-2-Clause），用于只读 SFTP 定位读取。版本由 `backend/go.mod` 和 `backend/go.sum` 锁定。SSH 握手沿用已有 `golang.org/x/crypto v0.59.0`（BSD-3-Clause）。引擎仍只依赖 Go 标准库，网络 I/O 只在后端。
- v0.1 只支持稳定追加的导出文件及部署方提供的不可复用代次标识。拉取前后核对代次和已消费前缀末端 SHA-256；截断、代次变化及锚点不符明确失败，保持已提交断点。读取仅消费 LF 结尾完整行，单次 4 MiB、单行 64 KiB，半行留待后续采集。该锚点不能证明整个前缀不变，部署者的追加保证仍是前置条件。
- 原始字节先写同卷不可变对象，SQLite 短事务提交批次、原始行、事件、断点、采集尝试、审计和分析意图。启动时清理无数据库引用的原文对象，校验已发布原文的长度与 SHA-256，恢复中断尝试及任务。全部解析失败或忽略的完整行形成 `diagnostic` 批次，不创建 ready 分析任务。

## 跨批次 Count 身份与快照

每个自动任务的不可变输入边界是所属批次的 `end_offset`。后端读取同一来源在该边界内已提交的全部事件，按事件时间、原始字节偏移和事件 ID 排序，再把它们交给现有引擎 `Run`。运行时使用 `source-scope-v2:<source_id>` 作为稳定逻辑输入身份；存储事件仍保留原批次 ID 和稳定原始位置。引擎 Count 算法和 `1.0.0` 语义未改，新的业务范围由 `source-scope-v2` 显式区分。

只有触发事件属于当前新批次的 Finding 才能发布。此前批次的触发结果参与窗口状态重建，但不再发布。告警指纹由稳定来源范围、规则版本/摘要、分组及触发事件身份决定；相同任务重跑比较完整结果摘要，只补任务关联，保留已有状态及证据。失败任务的结果在短事务外计算，正式告警、证据和任务成功状态在单次事务发布。

新增事件的时间若早于已提交来源事件，采集失败并保持断点，须通过独立回填流程处理。当前重放每批扫描固定历史前缀，成本随历史增长；未来增量状态算法须逐例与完整前缀金标准对照后再替换。Distinct、Sequence 和轮转后的跨代次上下文不在本次实现范围内。

## 验证与后续

测试覆盖四条失败在 A 批次、第五条在 B 批次且位于 300 秒闭合边界，产生一条含五条原始证据的告警；再追加第三批、重跑第二批，确认不重复且人工状态不被覆盖。另覆盖半行、断线、晚到事件、目录变化、原文篡改和任务入队故障时的断点与批次回滚。本地 SFTP 测试覆盖固定主机公钥、字节断点及自动采集到告警的链路；真实受控环境的只读隔离、轮转、容量与端到端延迟仍需 #11/#14 验收。
