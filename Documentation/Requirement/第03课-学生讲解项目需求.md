# 学生讲解项目需求（二）· SRS 定稿

## 一、本课目标

需求规约定稿：用例图完整、SRS v1.0 评审通过并发布

## 二、课堂流程（三段式）

| 环节 | 时长 | 内容 |
| --- | --- | --- |
| 教师引入 | 10′ | SRS 的结构讲解：功能需求（用例编号＋描述＋验收标准）、非功能需求（性能/安全/可用性）、约束条件。 |
| 学生讲解 | 8′×4–5 | 讲解完整需求：用例图（含主/次参与者）、场景描述、非功能需求。其他组提问。 |
| 评审签字 | 20′ | 教员逐组评审：需求是否可测试、是否完整、是否前后一致。通过者SRS v1.0 以 Release 发布。 |
| 布置 | 10′ | 课后任务：进入分析建模阶段。 |

## 三、课前准备（学生）

用例图完善；SRS 草稿已提交 PR

## 四、课后任务与提交物

- SRS v1.0 以 Release 发布（含变更记录）
- 需求追溯矩阵 v0：需求 ID ↔ 用例编号
- 建立需求变更通道（变更走 Issue＋PR，不走口头）

## 五、GitHub 检查点

SRS v1.0 Release＋追溯矩阵初版

## 六、参考资料

课件 Ch8 规约节与"提示词就是规约"专家框；课件 Ch9 用例三部曲

## 七、教师提示

> SRS 定稿不是"不变"——变更走 Issue＋PR 才是常态。没有变更记录的 SRS 反而可疑。
