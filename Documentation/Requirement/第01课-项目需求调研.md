第1 课 · 第9 周

# 项目需求调研（动员与启动）

## 一、本课目标

启动项目：完成组队选题、理解课程规矩、掌握调研方法、建立 GitHub 仓库

## 二、课堂流程（三段式）

| 环节 | 时长 | 内容 |
| --- | --- | --- |
| 教师引入 | 20′ | 课程宣贯：三大本质（过程/协作/质量内建）；GitHub 全流程留痕铁律——"不在仓库里发生的事视为没有发生"；AI 五总则：验证而非信任、规格先行、人守关卡、为再生成而设计、护密合规。 |
| 分组讨论 | 40′ | 组队（4–5 人，角色可兼任：组长、AI 使用负责人、DevOps 负责人、测试负责人）；选题讨论（自选真实业务背景的中等规模项目）；调研方法讲解：访谈、问卷、工单挖掘、竞品分析。 |
| 实操演示 | 20′ | GitHub 仓库初始化：创建组织、开启分支保护（main 只接受 PR）、Issue 模板（用户故事/缺陷/任务三模板）、Milestone 创建。 |
| 总结布置 | 10′ | 明确课后任务与下次课检查点；发《软件工程课程设计要求（版本2）》。 |

## 三、课前准备（学生）

预习《要求（版本2）》第一至四章；初步酝酿选题方向与队友

## 四、课后任务与提交物

- 完成组队并报备（组名、成员、角色分工）
- 创建 GitHub 仓库并开启分支保护
- 提交选题 Issue（含一句话项目描述）
- 完成调研计划表（调研对象、方法、分工、时间表）
- 选做加分：给 Star ≥ 100 的公开开源项目提交一个 PR 并被合并（改错别字、补文档都算），不能是自己或组员的仓库，期末答辩凭 Merged 链接加分并口头说明内容

## 五、GitHub 检查点

仓库建立＋选题 Issue＋调研计划表（下次课检查）

## 六、参考资料

《要求（版本2）》一至四章；课件 Ch8 过渡页与七任务总览；课件 Ch7 原则页（84 条守则——AI 时代更值钱）

## 七、教师提示

> 选题宁小勿大：一个能做完的校园二手交易平台，胜过一个做不完的"智能城市管理系统"。
