# DevOps 迭代方法 · 文档要求 · 答疑

## 一、本课目标

DevOps 实践落地＋最终文档清单宣贯＋集中答疑

## 二、课堂流程（三段式）

| 环节 | 时长 | 内容 |
| --- | --- | --- |
| 讲授 | 40′ | DevOps 八实践在项目中的落地映射：Issue 驱动开发（每件事一个Issue）→ PR＋Code Review（人守关卡）→ Actions CI（每次合并自动构建测试）→ Milestone（迭代节奏）→ Release（版本发布）。最终文档清单宣贯（八类交付物）；AI 证据包与《AI 使用报告》要求。 |
| 答疑 | 40′ | 集中答疑：技术栈选型、CI 配置、AI 使用边界、答辩准备——所有问题当场解答或指定课后跟进。 |

## 三、课前准备（学生）

迭代计划已确认；CI 已搭建（或有搭建中的 PR）

## 四、课后任务与提交物

- 编码迭代（课外约 50＋40 学时）：按 Milestone 推进
- Actions CI 通过（自动构建＋测试）
- 首个可运行版本打 Tag（如 v0.1.0）
- 最终答辩：线上线下结合，每组 20 分钟（演示 12′＋问答 8′）
- 选做加分提醒：给 Star ≥ 100 的公开开源项目提交 PR 并被合并的（改错别字、补文档、修 Bug 均可），期末答辩最后一页附 Merged 链接并口头说明 PR 内容与动机即可申请加分（文档+2/代码+3/封顶+5）。注意：不能是自己或本组成员的仓库。找入门机会：在 GitHub 搜索 label:"good first issue" 并筛选 Star ≥ 100，从文档改起。

## 五、GitHub 检查点

Actions CI 通过＋首个可运行版本 Tag

## 六、参考资料

课件 Ch5 敏捷开发（DevOps 工具表）；课件 Ch7 原则页；课程设计要求版本2 第六章考核

## 七、教师提示

"不在仓库里发生的事视为没有发生"——从今天起，每个功能、每次修复、每行代码都必须走Issue→PR→CI→Merge 流程。
