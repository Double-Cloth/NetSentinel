# 项目分析建模讨论

## 一、本课目标

掌握分析建模三张图：类图、状态图、顺序图——把"是什么"画出来

## 二、课堂流程（三段式）

| 环节 | 时长 | 内容 |
| --- | --- | --- |
| 微讲 | 30′ | 类图语法：类名/属性/操作/关联/多重性；状态图要素：状态/事件/守卫条件/动作；顺序图：按时间排的交互记录。常见错误演示。 |
| 组间互查 | 40′ | 每组将分析模型草稿（Mermaid 或PlantUML 源码）投屏，另一组检查：类图是否覆盖所有用例？状态图是否遗漏异常路径？顺序图是否与用例对应？ |
| 巡回答疑 | 20′ | 教员逐组巡回答疑，重点解决"该画多细"和"什么时候停"的问题。 |

## 三、课前准备（学生）

分析模型草稿（类图至少覆盖核心用例）

## 四、课后任务与提交物

- 分析模型完善：类图＋状态图＋顺序图
- 模型源文件（.mmd/.puml）入 models/ 目录
- 追溯矩阵更新：需求 ID ↔ 用例 ↔ 模型元素

## 五、GitHub 检查点

models/ 目录建立＋模型源文件 PR

## 六、参考资料

课件 Ch9 场景建模（活动图=分镜表、泳道图=片场分工）；课件 Ch10 类建模（语法分析→六条筛选→CRC卡）；课件 Ch11 行为建模（电梯比喻讲状态/事件/守卫）

## 七、教师提示

> 模型不是画得越细越好——教材经验法则第 2 条："抽象别太低"。画到能指导设计就够了，别陷进实现细节。
