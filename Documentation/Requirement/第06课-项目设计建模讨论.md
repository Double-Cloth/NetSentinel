# 项目设计建模讨论 · 学生讲解设计（一）

## 一、本课目标

概要设计：体系结构选型有据、数据库设计合理、接口契约清晰

## 二、课堂流程（三段式）

| 环节 | 时长 | 内容 |
| --- | --- | --- |
| 教师引入 | 10′ | 设计概念的 AI 时代含义：模块化= 上下文边界、高内聚低耦合 = AI可理解性、信息隐藏 = 提示词边界。概要设计三件套：架构图＋数据库 ER 图＋API 契约。 |
| 学生讲解 | 8′×4–5 | 讲解概要设计：选了什么架构风格（分层/微服务/单体）、为什么选（不选别的理由）；数据库表设计；内外接口定义。 |
| 点评 | 20′ | 教员点评：架构决策是否有 ADR记录？API 是否有OpenAPI/Swagger 文档？数据库是否满足三范式？ |
| 布置 | 10′ | 课后任务：完成详细设计。 |

## 三、课前准备（学生）

概要设计草稿（架构图＋数据库 ER＋接口文档）

## 四、课后任务与提交物

- 概要设计规约（评审签字）
- API 契约（OpenAPI 或等效接口文档）
- 架构决策记录 ADR（选型理由与备选方案）

## 五、GitHub 检查点

设计文档 PR＋ADR

## 六、参考资料

课件 Ch12 设计概念（盖房子比喻）；课件 Ch13 体系结构设计（公司组织架构比喻）；课件 Ch12 AI 页——"模块边界=上下文边界"

## 七、教师提示

> "选单体还是微服务"不重要——重要的是你说得清"为什么"。ADR 三行就够：选了什么、为什么、放弃了什么。
