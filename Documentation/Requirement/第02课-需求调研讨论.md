# 需求调研讨论 · 学生讲解需求（一）

## 一、本课目标

检验调研成果：从调研发现到用户故事的第一次转化

## 二、课堂流程（三段式）

| 环节 | 时长 | 内容 |
| --- | --- | --- |
| 教师引入 | 10′ | 回顾上次检查点；讲解用户故事写法：作为…我想…以便…＋Given/When/Then 验收标准；强调验收标准是后续测试和评分的依据。 |
| 学生讲解 | 8′×4–5 | 每组讲解调研发现：干系人是谁、业务目标是什么、现状痛点在哪。教员对照"调研深度与真伪"逐组点评。 |
| 点评研讨 | 20′ | 常见问题：把功能当需求（"要有搜索"是功能不是需求）；漏掉非功能需求（性能、安全）；干系人不全。 |
| 布置 | 10′ | 课后任务：完善用户故事清单，每条带验收标准，Issue 化入库。 |

## 三、课前准备（学生）

调研报告已 PR 合并；用户故事清单初稿（至少 10 条）

## 四、课后任务与提交物

- 用户故事清单完善（不少于 20 条用例，含非功能需求）
- 每条用户故事附 Given/When/Then 验收标准
- 全部 Issue 化并分配负责人

## 五、GitHub 检查点

用户故事 Issue 化＋验收标准入库

## 六、参考资料

课件 Ch8 需求工程七任务；课件 Ch9 场景建模总览；用户故事→验收标准→AI 测试链路（Ch8 琥珀案例）

## 七、教师提示

> "要快"不是需求——"在 2G 网络下 3 秒内加载完成"才是需求。验收标准写得越具体，后面测试和评分越顺。
