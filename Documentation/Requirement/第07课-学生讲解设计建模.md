# 学生讲解设计建模（二）· 迭代计划

## 一、本课目标

详细设计定稿＋编码迭代计划：里程碑拆分、测试策略、风险预案

## 二、课堂流程（三段式）

| 环节 | 时长 | 内容 |
| --- | --- | --- |
| 教师引入 | 10′ | 详细设计的深度控制：构件级设计画到"能指导编码"即可；迭代计划要素：Milestone 拆分（至少 2 个迭代）、每个迭代的验收标准。 |
| 学生讲解 | 8′×4–5 | 讲解详细设计与关键技术方案；展示迭代计划：第一个迭代做什么、怎么验收。 |
| 评审签字 | 20′ | 教员逐组评审设计规约；确认迭代计划可行性。通过者进入编码阶段。 |
| 布置 | 10′ | 课后任务：启动编码迭代，搭建CI。 |

## 三、课前准备（学生）

详细设计（构件级）；迭代计划草稿

## 四、课后任务与提交物

- 详细设计规约（评审签字）
- 部署图（含服务器/客户端/网络拓扑）
- 迭代计划确认：Milestone（至少 2 个）＋测试计划

## 五、GitHub 检查点

Milestone 规划＋测试计划

## 六、参考资料

课件 Ch12 构件级设计元素；课件 Ch13 ACD 语境图与部署图；课件 Ch5 敏捷开发

## 七、教师提示

> 迭代计划的最小颗粒度：第一个 Milestone 应该在 1–2 周内产出"能跑的功能切片"——不是"搭好框架"，而是"一个用户故事从头到尾能演示"。
