# NetSentinel 需求规格说明书（SRS）

版本 v1.0.0-rc.2，编制日期 2026-11-25，状态为待正式评审的发布候选。目标基线为 `srs-v1.0.0`；本候选不代表教师批准或产品已实现。关联 [WP-02b / #6](https://github.com/Double-Cloth/NetSentinel/issues/6)。本文定义业务结果与操作约束，算法及接口设计作为实现参考。正式冻结须完成[评审与发布记录](评审与发布记录.md)中的人工关卡。

## 1. 干系人与业务约束

### 1.1 来源、范围与优先级

需求输入为已合并的 [WP-02a 调研报告](../Planning/需求调研报告.md)、三份访谈纪要及[输入规格记录](../Planning/授权样本验证与输入规格记录.md)。本次引用仓库记录，不新增访谈或签字事实。发现的来源差异见评审记录，未获批准前均为候选决策。

根据用户转述的第 10 周教师建议（[需求变更 #58](https://github.com/Double-Cloth/NetSentinel/issues/58)），本系统以授权日志源的定时自动拉取、批次分析和主动告警为主流程，提供 Count、Distinct、两阶段 Sequence、规则版本、任务、告警证据及人工处置。部署限定单机 Compose、SQLite、Go 与 React。人工上传仅用于补录和测试。实时抓包、自动封禁、漏洞利用、常驻 Agent、分布式集群及 CLI/TUI 产品界面不在范围内；跨源 Join、任意多阶段规则和流式处理为增强候选。核心 FR 均为必须项，增量列表示交付顺序；NFR 贯穿每个增量。当前仅有基础框架及 Count 等实现，需求表不得作为业务验收通过声明。

术语：数据集为一次固定解析结果；规则版本为不可变配置；任务快照为数据集、规则版本集合与引擎语义版本的组合；Finding 为引擎命中；告警为持久化且可人工处置的逻辑对象；幂等请求与逻辑告警去重分别验证。

### 1.2 业务约束

真实调研建议覆盖一名实验室服务器管理员、一名承担日志排查任务的使用者和一名教师或审计检查者，分别记录现有流程、日志样例、可接受误报、处置职责、数据保存和性能期望。访谈由成员实际开展，记录时间、授权、问题、原始回答、需求结论及确认人。

系统面向同一组织内的共享日志空间。admin 负责日志源、采集计划、数据与规则管理，analyst 执行检测与处置，auditor 只读检查。日志须来自授权环境，展示和导出以实验脱敏样本为基础。内置规则给出可疑线索及其证据，人工根据上下文确认和处置。

离线数据集一旦进入 ready 状态，其文件、解析器版本、解析参数和事件内容固定。规则一旦发布，其内容、归一化规则与语义版本固定。分析任务创建时保存数据集、规则版本集合和引擎版本，后续规则启停与新版本发布仅影响新任务的默认选择。

## 4. 三个细化用例

### 4.1 UC-04 自动拉取并发布采集批次

前置条件为 admin 已配置并启用授权日志源，包含格式、主机、只读凭据引用和调度周期。触发为调度到期或 admin 重试。成功后产生不可变 ready 采集批次；手动上传仅用于历史补录和测试。

1. admin 验证目标、授权、格式、年份及时区，连接测试在超时与大小预算内采样；凭据不回显。
2. 调度以源配置版本和最近成功断点创建唯一采集尝试，同源只允许一个活动尝试。
3. 后端只读拉取已授权文件的新增完整行，保存源文件代次、偏移及受控原文，半行留待下一次。
4. 解析、错误行记录、UTC 排序与原始事件标识生成，保留有效/忽略/错误统计。
5. 有有效事件时事务发布 ready 批次、推进已提交断点并写审计和自动分析排队记录；系统失败不推进断点。无完整行记录空尝试；完整行全部忽略或报错时，保存诊断及已消费位置，不创建 ready 或自动分析，避免无限重读。
6. Web 展示最后成功、延迟、下次采集与批次分析状态；新命中自动进入告警工作台。

异常路径覆盖认证失败、断网、超时、轮转/截断、文件消失、未完成行、磁盘故障、无有效事件、格式或年份错误、重启和重复调度。失败保留可重试原因，不将来源离线显示为“无告警即健康”；轮转策略与跨批次语义须先通过评审。来源凭据停用或删除后停止新拉取，不销毁已发布证据。

### 4.2 UC-13 自动分析并发布告警

自动路径前置条件为受控服务身份、源已启用、批次 ready 及规则来源兼容；手动复核要求 admin/analyst 登录。成功后任务 succeeded，Finding、告警、任务关联、证据和 Outbox 作为完整结果可查询。

1. 采集发布自动排队，幂等键绑定源配置版本与批次；手动复核由用户选择数据集、规则及显式版本并提交 `Idempotency-Key`。
2. 服务验证并保存不可变快照，创建 queued 任务，重复请求返回同一任务。
3. Worker 领取任务，按固定排序读取事件并调用独立引擎。
4. 引擎输出 Finding 和指标，服务将结果写入任务专属 staging。
5. 引擎全部成功后，服务在事务中以指纹合并正式告警、证据、任务关联及通知记录。
6. 任务切换 succeeded，返回新增告警数、复用告警数、总命中数及耗时。

自动调度仅采用创建时绑定的已发布规则与服务身份，不复用用户会话。规则在执行期间发布新版本时，任务继续使用已保存快照。输入排序错误、资源预算超限或存储失败时，任务 failed 并保存阶段化错误，staging 不进入正式列表。服务中断后的运行任务标记 failed，用户可按原快照重跑。

活动图应含源授权及服务身份校验、自动触发、幂等分支、队列、引擎失败、事务回滚和告警发布。必要顺序图覆盖 Web、API、Worker、Engine、Repository 与 Outbox。

### 4.3 UC-19 处置告警

前置条件为告警 open 或 acknowledged，用户为 admin 或当前认领的 analyst。成功后当前状态、处置历史和审计一致。

1. 用户查看证据及命中解释，先认领 open 告警。
2. Web 获取告警 `row_version`，提交动作及必填理由。
3. 服务验证角色、当前负责人、状态转换和版本。
4. 使用条件更新并在同一事务中写处置历史、审计。
5. 前端刷新状态和时间线，保留当前筛选上下文。

另一用户已修改时返回 409 并提示刷新查看新状态。告警已关闭时拒绝再次变更终态，备注可由 admin 或原负责人追加。网络超时可用操作幂等键重新查询原结果，避免重复历史。重复分析沿用已存在告警的状态和负责人。

## 5. 关键状态与业务不变量

| 对象 | 状态转换 | 不变量 |
| --- | --- | --- |
| 数据集 | importing → ready / failed | ready 数据、解析配置和摘要固定，失败数据集不可启动分析 |
| 规则 | draft 的修订不断增加，publish 创建新 RuleVersion，enabled 控制默认选择 | 发布版本不可覆盖，编辑始终作用于草稿 |
| 分析任务 | queued → running → committing → succeeded，活动状态可 → failed | 每次执行只有一个终态，正式结果仅在 succeeded 的原子发布中出现 |
| 沙箱任务 | queued → running → succeeded / failed | 结果短期保留在沙箱命名空间，业务告警与通知均无写入 |
| 告警 | open → acknowledged → closed / false_positive | 认领者与处置历史一致，终态保留，重跑不更新处置字段 |
| 通知 | pending → sending → sent / retry_wait / dead | 同一逻辑告警与渠道最多一条自动通知，重试共享同一投递记录 |

Sequence 的内部阶段与业务任务状态分别描述，规则详细设计给出内部状态的转换条件。

## 6. 非功能预算与测量口径

以下为本候选拟采用的验收预算，正式评审需确认与调研吞吐目标的差异；测试报告填写实测结果，不将预算写为已测成绩。

| 维度 | 候选目标 | 测量方法 |
| --- | --- | --- |
| 确定性 | 相同数据集、规则版本及引擎语义版本，逻辑 Finding 完全一致 | 对规范化排序后的指纹、指标值与证据 ID 做比较，排除运行时间字段 |
| 幂等性 | 顺序/并发重跑均无重复逻辑告警，已处置状态保持 | 多次重跑与并发请求，比较唯一指纹、处置历史及自动 Outbox 数量 |
| 10,000 条链路 | 从导入请求开始至任务结果可查询，候选预算 30 秒以内 | 4 vCPU、8 GiB 内存、SSD、本地容器，包含上传、解析、排序、排队、引擎和提交，排除人工停留 |
| 100,000 条引擎 | 8 条规则，预排序事件，候选预算 10 秒以内、引擎进程峰值 RSS 512 MiB 以内 | 预热 1 次、测量 5 次，输出中位数和最慢值，核对结果 |
| 100,000 条完整链路 | 候选预算 120 秒以内、后端峰值 RSS 1 GiB 以内 | 从导入至结果可查询，分别报告解析、排序、读取、引擎、提交和总耗时 |
| 常规查询 | 100,000 事件与 10,000 告警下，列表查询 p95 500 ms 以内 | 本机 API 连续 100 次并记录筛选条件，包含数据库耗时 |
| 权限 | 权限矩阵全部写接口越权拒绝，审计可追溯 | 直接调用 API 验证 401/403，前端按钮控制同步检查 |
| 可靠性 | 失败任务无正式部分结果，成功任务可追溯原始证据 | 注入解析、引擎、提交、重启和通知故障 |
| 部署 | 干净环境按说明启动并通过固定夹具烟测 | 保留镜像、配置、迁移、版本与完整执行记录 |

系统的引擎输入以事件数计量，文件导入以原始行数计量。全链路吞吐使用有效事件数除以全链路秒数，引擎吞吐使用引擎处理事件数除以引擎墙钟秒数，同时记录规则数、总匹配数、输出数与错误行数。

## 8. 输入、检测与错误契约

输入限定 UTF-8 明文 Nginx combined、固定模板 Nginx JSON、SSH RFC3164/RFC3339。RFC3164 必须给出 year/timezone，同一文件不跨自然年；DST 歧义或不存在时间拒绝并提示明确偏移。状态码仅接受 100—599，非法请求行记录 REQUEST_INVALID，独立 Invalid user 行忽略以避免重复计数。无效 UTF-8 记录解析错误，原文仅安全转义展示；单行候选上限 64 KiB，文件候选上限 200 MiB，超长内容不进入普通页面，保留原始文件引用、行号及错误码。上述容量与解析差异须经评审确认。统计满足 total=valid+ignored+error；无有效事件、参数缺失或系统故障不得发布 ready。

事件采用 UTC 微秒，按 `(event_time_us,line_no)` 排序，event_index 严格递增。窗口为 `[t-W,t]`，仅删除小于左边界事件。Count/Distinct 在阈值进入周期触发；Sequence finish 优先并消费此前 start，每次 Run 状态隔离。任务失败不发布部分正式告警；重跑保留既有负责人、状态及历史，快照版本不兼容时明确拒绝。

规则样例 R-001—R-008 暂按[引擎设计第 8 节](../Planning/03_独立规则引擎详细设计.md)及 TE 测试向量作为可复现候选；它们与调研规则并非全部一致，评审项 RV-01 未关闭前不得宣称阈值已确认。规则命中仅是安全线索，不等于证明账号失陷。

匿名业务请求返回 401，已登录但无权限返回 403；版本或幂等键内容冲突返回 409；合法异步任务返回 202 与任务 ID。写操作执行后端权限、CSRF 和审计校验；成功业务变更与审计同事务。前端不得通过固定成功响应代替未实现操作。ready 数据、已发布规则、任务快照和证据不可覆盖。

原始数据与 SQLite 位于同一受控持久化卷，禁止公开凭据、会话及 webhook。数据保留期限、授权证据和备份责任须由部署方在正式评审时确认；本候选不提供自动删除 ready 数据能力，也不把访谈中的法律描述作为合规结论。

## 9. 自动化与前端验收补充

自动拉取是后端的周期批次采集，不把 engine 改为网络客户端或无限流处理器。具体连接协议首轮拟评估只读 SSH/SFTP，亦可使用经批准的受控日志端点；协议、库、凭据注入、目标与路径白名单、主机身份验证通过 WP-04/ADR 后实现，本次不引入依赖、不关闭主机校验。

候选调度周期为 60 秒，可由 admin 在部署允许范围配置。正常环境下，从日志完整行在源端可读取到站内告警可查询的预算为一个调度周期加 30 秒；记录源新鲜度、采集/排队/分析/提交耗时，飞书另计发送与重试延迟。源离线或积压时显式显示降级，不承诺硬实时。性能预算与容量均待评审，原人工导入基准不得作为自动链路延迟结果。

跨批次阈值和 Sequence 不得丢失边界内事件；同一原始事件必须有跨拉取稳定的源标识、文件代次与位置身份。ready 批次不追加；输入使用完整不可变快照，并考虑最大规则窗口的上下文。旧 fingerprint 含 dataset_id，不能直接声称已满足跨批次去重；稳定分析范围、触发身份、重叠上下文及水位/迟到处理必须在 WP-04 和 WP-11 制定 ADR、兼容方案与测试，必要时提升语义版本。尚未支持的日志轮转或迟到模式应明确失败，不能静默漏报。

前端遵循 DESIGN.md 的中文、白底、深蓝文字、深青强调与现有 React/fetch/CSS，不新增框架或装饰性重设计。工作台优先展示待处置告警、源健康与数据新鲜度、采集失败与通知失败；告警证据最多两次导航可达。源设置提供连接测试、参数校验、计划启停与有权限的重试；日志源读取对三角色可见，凭据仅 admin 可写且任何角色均不可读回。375px 小屏与桌面均可使用；键盘焦点、label、状态文字、列表横向滚动、URL 筛选恢复、加载/空/错/重试及 401/403/409 不丢输入均为验收项。不得用虚构趋势、假告警或固定在线状态填充界面。
